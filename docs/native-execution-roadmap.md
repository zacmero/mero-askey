# Road to a minimal native execution proof

Owner-approved direction, 2026-10-31. RAM allocation, inert placement, independent mailbox readback and cleanup are already verified in ASKEY-NET-009. No custom program has executed.

1. **Instruction mode and cache handling — COMPLETE.** Traced and verified resident cache routines and copy-to-execution ordering against captured runtime `b104789b795630eee7de1b50d64e49710535221f8baa6652021af6d00abb3941`. Resolved RLX CP0 register 20 cache control bits (bit 1 = I-cache invalidate, bit 9 = D-cache invalidate), verified range D-cache writeback `0x800065ec` (`cache 0x15` loop on packet payload pointers) and global I-cache invalidate `0x801679e8` (invoked post-memcpy at boot). Even entry address guarantees MIPS32 execution mode under `webdll`. Detailed contracts recorded in [instruction-mode and cache contracts](../research/instruction-mode-cache-contracts.md) and [step-1 checkpoint](../research/instruction-cache-checkpoint.md).
2. **Prepare a minimal entry and returned callback — COMPLETE.** Assembled and verified 576-byte position-independent MIPS32 payload adhering strictly to the `webdll` two-call contract (`f(magic, iface) -> next_fn; next_fn(magic, iface)`). Preserves all callee-saved registers and stack, uses PC-relative discovery (`bal`), and writes 10 verification words (nonces, captured arguments, "ENTR", "CLNP", "SUCC") into the 64-byte mailbox at offset 512. Tool and contracts documented in [native payload design](native-payload.md) and [`tools/build_native_payload.py`](../tools/build_native_payload.py).
3. **One bounded execution trial — CURRENT / NEXT.** Create fresh owned RAM storage via `xfile`, revalidate allocation and payload pointers, place the compiled binary, apply cache coherency, invoke `webdll <entry_addr>`, and capture execution responses. Never reuse released addresses.
4. **Independent proof and cleanup.** In a fresh connection, verify nonce, entry and cleanup markers, confirm CLI responsiveness, then close/delete the owned allocation and verify the original inventory. Record actual results and hashes; a prompt alone is not execution proof.

Each step receives a documentation/commit checkpoint. Firmware writes, resets, persistent service/settings changes and hardware connections are outside this road unless separately instructed. A successful marker program is a native-execution milestone; an interactive OS shell remains a separate goal.
